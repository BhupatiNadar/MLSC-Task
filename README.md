# MLSC-Task: Hallucination Detection in Generative AI

## 1. Project Overview & Objective
This repository contains a comprehensive machine learning pipeline designed to detect hallucinations in responses generated by Large Language Models (LLMs). The core objective is to predict whether a given model's response is:
- **`GROUNDED`**: The response is fully supported by the provided source documents.
- **`PARTIALLY_GROUNDED`**: The response contains some supported facts but also includes unsupported claims.
- **`HALLUCINATED`**: The response is entirely unsupported by or contradicts the source documents.

This is a classic Natural Language Inference (NLI) and factual consistency checking problem, which is critical for ensuring the reliability of Retrieval-Augmented Generation (RAG) systems.

---

## 2. Dataset & Exploratory Data Analysis (EDA)

### Dataset Source
The primary dataset used for these experiments is the `hotpotqa` subset of the **`rungalileo/ragbench`** dataset, loaded via the HuggingFace `datasets` library.

### Data Cleaning & Preprocessing
During the Exploratory Data Analysis phase, several critical preprocessing steps were undertaken:
1. **Column Inspection**: The raw dataset contains rich metadata, including `question`, `documents`, `response`, and various automatic evaluation scores (`trulens_groundedness`, `ragas_faithfulness`, etc.).
2. **Label Filtering**: The target variable `label` was strictly filtered to include only the three valid classes (`GROUNDED`, `HALLUCINATED`, `PARTIALLY_GROUNDED`). Any malformed or invalid rows were dropped.
3. **Class Distribution Analysis**: The data exhibited a severe class imbalance:
   - **Grounded**: ~47,265 samples
   - **Hallucinated**: ~40,397 samples
   - **Partially Grounded**: ~7,515 samples
   
   This skew, particularly the lack of "Partially Grounded" examples, necessitated specific sampling strategies during model training.

---

## 3. Feature Engineering Approaches

To build robust classification models, two entirely different paradigms of feature extraction were explored:

### Approach A: Lexical Features (TF-IDF)
To establish a strong classical machine learning baseline, we utilized a Bag-of-Words approach.
- **Methodology**: The `question`, `documents`, and `response` text fields were concatenated into a single string for each instance.
- **Vectorization**: A `TfidfVectorizer` was applied with `ngram_range=(1, 2)` to capture both single words and bigrams, limited to `max_features=10000` to prevent memory explosion and overfitting.

### Approach B: Semantic Embeddings & Similarity Metrics
Because TF-IDF struggles with synonyms and paraphrasing, a semantic approach was also implemented using pre-computed dense vector embeddings.
- **Embeddings Used**: Dense vectors representing the `question_embeddings`, `document_embeddings`, and `response_embeddings`.
- **Similarity Features**: Three distinct cosine similarity metrics were explicitly provided to the model:
  1. `doc_response_similarity`
  2. `question_response_similarity`
  3. `question_document_similarity`
- **Feature Vector**: The final feature vector for each row consisted of the three embeddings concatenated with the three similarity scores (resulting in a dense vector of size 1152+).

---

## 4. Modeling & Handling Class Imbalance

### Balancing the Dataset
Because the "Partially Grounded" class was significantly underrepresented, models trained on the raw data would naturally become biased toward predicting "Grounded" or "Hallucinated."
To resolve this, **SMOTE (Synthetic Minority Over-sampling Technique)** was applied to the training set (`random_state=42`). This algorithm synthesized new examples for the minority class, ensuring the model saw a perfectly balanced distribution during training (e.g., 37,812 samples per class).

### Experiments & Results
All models were evaluated using an 80/20 train-test split (stratified). The primary evaluation metric chosen was **Macro-F1**, as it treats all classes equally regardless of their frequency in the test set.

1. **Logistic Regression (TF-IDF Baseline)**
   - *Parameters*: `max_iter=1000`
   - *Result*: Macro-F1 = 0.32
   - *Observation*: Struggled significantly with the minority class, failing to capture the nuance of partial hallucinations.

2. **Logistic Regression (Semantic Embeddings + SMOTE)**
   - *Parameters*: `class_weight="balanced"`, `max_iter=1000`
   - *Result*: Macro-F1 = 0.589 (Accuracy = 65.5%)
   - *Observation*: A massive improvement over the TF-IDF baseline for Logistic Regression, proving the value of semantic similarities.

3. **Linear Support Vector Classifier - SVC (Semantic Embeddings + SMOTE)**
   - *Result*: Macro-F1 = 0.595 (Accuracy = 65.9%)
   - *Observation*: Slight improvement over Logistic Regression on the embedding space.

4. **Linear Support Vector Classifier - SVC (TF-IDF)**
   - *Result*: **Macro-F1 = 0.66**
   - *Observation*: Surprisingly, the SVC trained on the 10,000 TF-IDF features yielded the best overall Macro-F1 score across our experiments.

**🏆 Best Model**: The **LinearSVC with TF-IDF features** currently serves as our champion model. It provides the strongest and most reliable classification across the three categories.

## 5. Limitations & Future Work

### Current Limitations
While the TF-IDF SVC model performs best empirically on this specific dataset split, relying on lexical overlap has fundamental flaws in production RAG systems. It cannot detect when an LLM cleverly paraphrases a hallucination or contradicts the text using completely different vocabulary. Furthermore, compressing the entire context into a single concatenated string loses the directional relationship (Does A entail B?).

### Roadmap for Production-Grade Accuracy
To push the Macro-F1 score higher and build a truly semantic hallucination detector, the following steps are recommended:

1. **Gradient Boosting on Semantic Features**:
   - Instead of using linear models (Logistic Regression, LinearSVC) on the embeddings, we should train **XGBoost** or **LightGBM**. These tree-based models are vastly superior at capturing non-linear interactions between similarity scores and embedding dimensions.

2. **Cross-Encoder Architecture (NLI)**:
   - The gold standard for factual consistency is treating the problem as Natural Language Inference.
   - We recommend fine-tuning a `DeBERTa-v3-small` or `RoBERTa-large` model using a Cross-Encoder setup. The input format would be `[CLS] Document Context [SEP] LLM Response [SEP]`, allowing the transformer's attention mechanism to directly compare words in the response to words in the document.

3. **LLM-as-a-Judge**:
   - Utilize a strong open-source instruct model (e.g., `Llama-3-8B-Instruct`) with a few-shot prompt to act as the evaluator.

### Production Deployment & Engineering
Once a champion model is finalized, the following MLOps pipeline should be established:
1. **API Development**: Wrap the prediction logic using **FastAPI** (`main.py`) to expose a REST endpoint (`/predict`).
2. **Confidence Thresholding**: Implement a logic layer that returns `UNKNOWN` or triggers a human-review fallback if the model's prediction probability falls below a certain threshold (e.g., < 0.60).
3. **Containerization**: Dockerize the application to ensure environment consistency.
4. **Monitoring**: Track incoming queries and responses to detect data drift, logging edge cases for continuous active learning.
